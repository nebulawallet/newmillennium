## Data flow

1. `data/**/*.json` is turned into a `ContentDB` by `compileContent()`. The same code path runs in `validate-data`, the Vite plugin and the tests.
2. In the browser, `/content/bundle.json` is loaded and `fromBundle()` rebuilds the `ContentDB`.
3. `createInitialState(db, map)` builds the GameState for 1 January 2000.
4. `Simulation.step()` advances one day and runs each system's daily, weekly, monthly and yearly hooks.
5. The UI reads the state through `Session` and the `version` signal.

**Adding a system.** Write an object implementing `System` in `src/sim/` and add it to `defaultSystems()` in `src/sim/simulation.ts`. Keep its state in `GameState` and its rules in `data/`.

**Adding a map mode.** Add an entry to `MAP_MODES` in `src/render/mapModes.ts` and an icon mapping in `src/ui/MapUi.tsx`.

**Adding a tab panel.** Flip its `phase` to `null` in `src/ui/tabs.ts` and render it in `LeftPanel` (`src/ui/hud/Panels.tsx`).

## Key invariants

- **Office tenure** lives only on office `holders`. `holdersOn(office, date)` treats `to` as exclusive.
- **Validation:** every rule is in `compile.ts`. The core tier is the Pass A requirement; the full tier adds cabinet, military, continuity and opposition depth.
- **Saves** store the GameState plus a content hash. Content stays in the bundle and is never saved.
- **Map:** province id = index + 1; id 0 = sea. Coordinates are x = longitude, y = Miller y, covering latitudes −58° to 84°.
